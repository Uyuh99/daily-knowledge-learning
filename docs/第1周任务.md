# 第 1 周：项目基础与只读 Vault 扫描

## 学习目标

完成本周后，你应能解释并实际使用：

- Git 仓库、提交、分支和回滚。
- `uv` 虚拟环境与 `pyproject.toml`。
- Python 模块、`pathlib`、异常和类型标注。
- pytest 如何验证业务规则。
- 为什么真实 Vault 在第一阶段只能只读扫描。

## 阅读范围

- Pro Git 中文版第 1、2、3 章。
- Python 官方教程中模块、文件读写和异常相关章节。
- 不观看长篇 Agent 视频，不安装 LangChain。

## 已提供的起点

仓库已有一个最小只读扫描器和测试。先运行：

```powershell
uv sync
uv run pytest
uv run daily-learning .\tests\fixtures\vault_minimal
```

然后阅读以下文件，不要先改代码：

1. `src/daily_knowledge_learning/models.py`
2. `src/daily_knowledge_learning/vault_scan.py`
3. `tests/test_vault_scan.py`

## 你的编码任务

1. 为扫描器增加一个明确的 `--subject` 参数，只显示心理学或经济学。
2. 增加一个测试：没有 `02-交流后版.md` 的主题不能被标记为已学。
3. 增加一个测试：`status: 暂缓` 被识别为暂缓。
4. 改进 CLI 的错误提示：Vault 路径不存在时返回非零退出码。
5. 处理同一日期和主题同时存在旧单文件与三版本目录的情况：当前主题只显示一次，并保留“存在旧版记录”的提示。
6. 为每项修改分别提交 Git commit，提交信息说明行为变化。

## 提交给导师的材料

- `git diff` 或提交哈希。
- `uv run pytest` 的输出。
- CLI 的运行输出。
- 一段 300–500 字复盘：为什么“有文件”不等于“已学”。

## 验收标准

- 所有原有测试通过。
- 新增测试能证明状态规则，而不是只覆盖代码行。
- 没有修改真实 Vault。
- 没有提交密钥、私人笔记或 `.venv`。

## 当前已知限制

第一周扫描器只依据主题目录和版本文件的 YAML 状态判断，不解析学习地图中的人工状态，也不把旧单文件中的内容自动判定为已学。这是有意保守的起点；第 3 周再实现索引核对和更完整的兼容策略。
